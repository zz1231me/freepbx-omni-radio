# omni-radio

> **인터넷 라디오 for FreePBX 17 / Asterisk**
> 내선 **7200** 하나. 걸면 화면에 채널 목록이 뜨고, 번호를 누르면 그 방송이 나옵니다.
> 설치는 명령 한 줄, 웹에서 할 일 없음. 아무도 안 들을 때는 방송을 받지 않습니다.

## 어떻게 쓰나

```
  7200 걺 ──▶ (콜백이 옴) ──▶  화면: 채널을 고르세요
                                      │
                                      ▼
                              [1]YTN라디오 [2]TBS FM     ← 화면 폭에 맞춰
                              [3]EBS FM [4]AFN한국          묶어서 넘김
                              [5]아리랑라디오
                                      │
                              번호를 누르면
                                      ▼
                              ♪ 그 방송이 나옵니다
                                      │
              듣는 중에도  1~9 다른 채널 / * 또는 0 목록 / # 종료
```

| 키 | 하는 일 | 화면 |
|---|---|---|
| **1~9** | 그 번호 채널로 (목록에서든 듣는 중이든) | `[2]TBS FM >[*]목록` |
| **\*** 또는 **0** | 채널 목록으로 (소리는 계속 나옵니다) | `채널을 고르세요` → `[1]YTN라디오 [2]TBS FM` |
| **#** | 종료 (어디서 누르든) | `라디오 종료` |
| (무입력) | 목록에서 세 바퀴 / 듣는 중 2시간이면 끊음. 아무리 오래 들어도 3시간 | |

**안내는 전부 화면입니다.** 소리는 라디오가 내고 있습니다. 그 위에 대고
"채널을 선택하세요"라고 말하면 방해만 됩니다. 그래서 음성 조각을 만들 일이
없고, TTS 도 API 키도 안 씁니다.

**목록을 넘기는 도중에도 아는 번호를 바로 누르면 됩니다.** 끝까지 볼 필요가
없습니다. 한 화면에 몇 개가 들어가는지는 이름 길이를 보고 정합니다.

**어느 자리에서 누르든 키는 같게 동작합니다.** 목록을 보는 중이든, 듣는
중이든, 오입력 안내가 떠 있든 마찬가지입니다. 키를 `Read()` 가 아니라
`WaitExten` 으로 받기 때문입니다 — `Read()` 는 `#` 을 '입력 끝' 으로 삼아
삼켜 버려서, 그걸 쓰면 메뉴에서 `#` 을 눌러도 아무 일이 안 일어납니다.

**없는 번호를 눌러도 통화는 안 끊깁니다.** 화면으로 알리고, 그 2초 동안에도
제대로 된 번호를 누르면 바로 먹습니다.

**소리가 안 날 것 같으면 화면이 미리 알려 줍니다.** `[3]EBS FM (안나옴)` 은
방송국에 못 붙고 있다는 뜻, `(준비안됨)` 은 그 채널의 스트림이 한 번도 안 떴다는 뜻입니다.
조용한 이유를 모르는 것이 제일 나쁩니다.

**음량은 전화기 자체 볼륨으로 맞추세요.** 방송국끼리 음량이 다른 것만
설정에서 `gain_db` 로 잡습니다.

## 설치

```bash
sudo ./install-radio.sh
```

끝입니다. **웹에서 할 일이 없습니다.** 바로 7200 을 걸면 됩니다.
ffmpeg 가 없으면 알아서 깝니다.

번호를 바꾸려면 `--number 7250`. 그 번호가 이미 쓰이고 있으면 넣기 전에
멈추고 알려 줍니다 — 조용히 덮어써서 남의 내선이 안 걸리게 되는 쪽이 훨씬
나쁩니다.

### 왜 웹 작업이 없나

FreePBX 에서 보통은 **Custom Destination** 과 **Misc Application** 두 개를
손으로 만들어 이어야 합니다. 둘 중 하나를 빠뜨리면 "번호를 눌러도 아무 일이
없다" 가 되는데, 그때 어디를 봐야 하는지 알기 어렵습니다.

대신 다이얼플랜에 한 줄을 넣습니다.

```
[from-internal-custom]
exten => 7200,1,Goto(radio-entry,s,1)    ; omni-radio-number (radio-gen.py 가 관리합니다)
```

`from-internal-custom` 은 FreePBX 가 제일 먼저 읽는 곳이라 이 번호가 이깁니다.
바로 그 이유로 **실제 내선과 겹치면 그 내선이 조용히 안 걸립니다.** 그래서
넣기 전에 확인하고 `verify.sh` 가 매번 다시 봅니다. 표시(`; omni-radio-number`)로
찾아 지우고 다시 넣으므로 번호를 몇 번 바꿔도 줄이 쌓이지 않고, 같은 파일에
적어 둔 남의 내용은 건드리지 않습니다.

## 채널 바꾸기

### 파일을 고치면 끝입니다

```bash
sudo nano /etc/asterisk/radio-stations.json
```

**저장하면 몇 초 뒤 알아서 반영됩니다.** 명령을 더 칠 필요도, Apply Config 도,
재시작도 없습니다. `radio-watch.path` 라는 systemd 감시 단위가 이 파일만
지켜보다가 반영을 돌립니다.

**편집하다 JSON 을 깨뜨려도 듣던 라디오는 안 죽습니다.** 반영은 채널 목록을
먼저 검사하고 통과할 때만 진짜 설정을 덮습니다. 깨져 있으면 아무것도 바꾸지
않고 옛 설정 그대로 계속 틉니다. 이유는 로그에 남습니다.

```bash
tail /var/log/asterisk/radio.log
# APPLY-FAIL ... (JSON 문법): Expecting ',' delimiter  (옛 설정 그대로 둡니다)
```

### 명령으로 해도 됩니다

이쪽은 넣기 전에 실제로 틀어 봅니다.

```bash
sudo radio-gen.py --add 6 국악방송 http://mgugaklive.nowcdn.co.kr/gugakradio/gugakradio.stream/playlist.m3u8
sudo radio-gen.py --del 6
```

이름에 공백이 있어도 따옴표 없이 됩니다 — `--add 6 국악 방송 http://...`
처럼 써도 주소를 기준으로 갈라 줍니다.

### 설정 항목

```json
{
  "number": "7200",
  "rate": 16000,
  "idle_sec": 7200,
  "on_demand": true,
  "linger_sec": 60,
  "max_sec": 10800,
  "audio": "soft",
  "stations": [
    { "key": "1", "name": "YTN라디오", "url": "https://radiolive.ytn.co.kr/...", "gain_db": 0 }
  ]
}
```

| 항목 | |
|---|---|
| `number` | 전화기에서 누를 번호 |
| `key` | 채널 번호. **1~9** 만 (0 과 `*` 는 목록, `#` 는 종료라 못 씁니다) |
| `name` | 화면에 뜨는 이름. 한글 8자 안쪽이 잘 보입니다 |
| `url` | 스트림 주소. MP3 / AAC / OGG / HLS 다 됩니다 (ffmpeg 가 읽습니다) |
| `gain_db` | 방송국끼리 음량 맞추기. 작으면 `3`, 크면 `-3` 정도 |
| `rate` | `16000` (G.722) 또는 `8000` (G.711 만 쓰는 환경) |
| `idle_sec` | 듣는 중 아무것도 안 누를 때 끊기까지의 초 |
| `on_demand` | `true` 면 듣는 사람이 있을 때만 받습니다 |
| `linger_sec` | 마지막 사람이 끊고도 더 받아 두는 초 (기본 60) |
| `max_sec` | 아무리 오래 들어도 끊는 초 (기본 10800 = 3시간) |
| `audio` | 소리 보정. `off` / `soft`(기본) / `clear` |

### 소리 보정

전화는 대역이 좁습니다(G.722 기준 50~7000Hz). 그 안에서 나아질 여지가 있어
`audio` 로 고릅니다.

| 값 | 하는 일 |
|---|---|
| `off` | 아무것도 안 함 |
| **`soft`** (기본) | 전화가 못 내는 낮은 소리를 걷어내고(`highpass=80`), 44.1kHz→16kHz 줄이기를 **soxr** 로 합니다 |
| `clear` | 거기에 음량 고르기(`dynaudnorm`)까지. 작은 소리가 잘 들리는 대신 조용한 구간의 잡음도 같이 떠오릅니다 |

`soft` 는 부작용이 없어서 기본으로 켜 뒀습니다. **soxr 은 ffmpeg 빌드에
없을 수도 있어서, 껍데기가 시작할 때 한 번 시험해 보고 없으면 기본
리샘플러로 넘어갑니다.** 어느 쪽을 썼는지는 로그에 남습니다.

```bash
grep 리샘플러 /var/log/asterisk/radio-stream.log
```

### 주소를 모를 때

```bash
sudo radio-gen.py --find 재즈
sudo radio-gen.py --find classical
```

radio-browser.info 에서 찾아 **그대로 실행할 `--add` 명령**까지 만들어 줍니다.

**국내 지상파(KBS·MBC·SBS)는 이 방법으로 안 됩니다.** 재생할 때마다 서명과
토큰이 붙는 주소라 고정 URL 이 없습니다. 토큰만 떼고 원본을 열어 보면
이렇습니다.

```
KBS 쿨FM    https://2fm-ad.gscdn.kbs.co.kr/2fm_ad_192_1.m3u8    → 403 Forbidden
SBS 파워FM  https://radiolive.sbs.co.kr/powerpc/powerfm.stream/  → 403 Forbidden
MBC FM4U    https://minimw.imbc.com/dmfm/_definst_/mfm.stream/   → 400 Bad Request
```

KBS 는 CloudFront 서명(`Policy=`), SBS 는 JWT(`token=`), MBC 는 세션
파라미터(`_lsu_sa_=`)를 붙입니다. 전부 시간이 지나면 만료돼서 설정 파일에
박아 둘 수가 없습니다.

굳이 넣으려면 토큰을 대신 받아 주는 중계를 쓰는 수밖에 없습니다
([BSofDeath/radio.bsod.kr](https://github.com/BSofDeath/radio.bsod.kr) 이
Cloudflare Workers 로 그런 걸 돌립니다). 다만 **남이 개인적으로 돌리는
서비스**라 내려가면 그날로 안 나오고, 라이선스나 이용약관이 적혀 있지
않습니다. 집에서 혼자 듣는 정도를 넘어선다면 권하지 않습니다.

## 확인과 문제 해결

라디오는 잘못돼도 증상이 "무음" 하나뿐입니다. 그래서 **어디서 끊겼는지**
짚어 주는 도구를 먼저 보세요.

```bash
sudo radio-verify.sh
```

```
1. 파일이 제자리에 있는가       (권한, 로그 주인, ffmpeg)
2. 채널 목록을 읽을 수 있는가    (JSON 문법, key 규칙)
3. Asterisk 가 클래스를 아는가   (#include, format=slin16)
4. 껍데기가 떠 있는가           (채널 수만큼) + 못 붙는 채널 이름
5. 다이얼플랜                   (컨텍스트, AGI 모드, 구조 회귀)
6. 번호가 붙어 있는가           (그 번호가 정말 라디오로 가는가, 자동 반영이 도는가)
```

```bash
sudo radio-gen.py --status
```

```
방송 수신: 듣는 사람이 있을 때만  (마지막 사람이 끊고 300초는 더 받아 둠)

  번호  채널            상태      듣는중   마지막 변화   비고
  ────────────────────────────────────────────────────────────────────
  1번   YTN라디오       받는중    2명      1초 전
  2번   TBS FM          쉬는중    0명      12분 전
  3번   EBS FM          안나옴    0명      2분 전        rc=1 연속실패 4

  껍데기 5/5개 떠 있음, ffmpeg 1개 돌고 있음
```

**껍데기는 채널 수만큼 항상 떠 있고, ffmpeg 는 듣는 사람이 있을 때만 돕니다.**
그래서 "ffmpeg 가 0개"는 통화가 없을 때의 정상입니다. 개수만 세면 오해합니다.

```bash
sudo radio-gen.py --check 2                  # 2번 채널만 실제로 틀어 보기
sudo radio-gen.py --reset                    # 청취자 표시 전부 지우기 (사고 뒤 청소)
tail -f /var/log/asterisk/radio.log          # 누가 언제 뭘 들었나
tail -f /var/log/asterisk/radio-stream.log   # 켜지고 꺼지고 다시 붙은 기록
sudo asterisk -rx 'moh show classes'
sudo asterisk -rx 'dialplan show radio-play'
```

`--check` 는 **통화에서 쓰는 바로 그 경로를 5초 돌려 보고** 몇 초치 오디오가
나왔는지 셉니다. "주소가 살아 있다"만 보는 것과 다릅니다. 코덱이 안 맞아서
주소는 멀쩡한데 소리만 안 나는 경우까지 여기서 걸립니다.

## 파일이 하는 일

| 파일 | 하는 일 |
|---|---|
| `stations.json` | **채널 목록. 사용자가 고치는 유일한 파일입니다** |
| `radiolib.py` | 그 목록을 읽고 검사하는 코드. **읽는 코드는 여기 하나뿐입니다** |
| `radio.agi` | 채널 목록을 화면 꼴로 만들기, 채널 선택, 청취자 표시, 콜백 |
| `radio-gen.py` | 목록 → MOH 클래스, 번호 붙이기, 채널 추가·삭제, 실측 확인, 상태 보기, 주소 검색 |
| `radio-stream.sh` | 스트림 하나. **듣는 사람이 있을 때만 받고, 끊기면 다시 붙습니다** |
| `extensions_custom-radio.conf` | 메뉴와 흐름. AGI 가 준 클래스를 틀기만 합니다 |
| `replace-blocks.py` | 옛 다이얼플랜을 표시 구간째 교체 (여러 번 돌려도 안 쌓임) |
| `verify.sh` | 여섯 군데를 따로 확인 |
| `radio-watch.path` / `.service` | **채널 목록을 저장하면 알아서 반영** |
| `radio-logrotate` | 로그가 무한정 커지지 않게 |

**채널을 늘리거나 이름을 바꿀 때 고치는 곳은 `stations.json` 하나뿐입니다.**
다이얼플랜에는 채널 이름도 주소도 들어 있지 않습니다. 양쪽에 나눠 두면
한쪽만 고쳤을 때 "화면에는 3번이 보이는데 누르면 무음"이 됩니다.
그 증상은 소리만 들어서는 원인을 못 찾습니다.

전체 구조는 이렇게 나뉩니다.

```
   통화 쪽 (전화가 오면 시작)              스트림 쪽 (Asterisk 뜰 때부터 계속)
   다이얼플랜 + radio.agi                  radio-stream.sh × 채널 수
            │                                        │
            └──── live/radio3/<통화ID> ───────────────┘
                  이 파일이 있냐 없냐. 그게 전부입니다.
```

둘은 서로 함수를 부르거나 기다리지 않습니다. 통화 쪽은 "누가 3번을 듣고
싶어 한다"고 파일을 하나 만들 뿐이고, 스트림 쪽은 그 파일을 보고 ffmpeg 를
켜고 끌 뿐입니다. 하나가 죽어도 나머지가 안 멈춥니다.

## 설계 — 왜 이렇게 했나

### 아무도 안 들으면 안 받습니다

이게 이 프로젝트에서 제일 중요한 부분입니다.

Asterisk 의 음악대기(MOH) 클래스는 **등록되는 순간 프로그램을 띄우고 통화가
하나도 없어도 계속 띄워 둡니다.** 그대로 두면 128kbps 채널 3개 = **하루 4GB** 를
아무도 안 듣는 방송에 씁니다. 집에 둔 서버에서는 무시할 수 없는 양입니다.

그래서 스트림 껍데기(`radio-stream.sh`)가 지금 듣는 사람이 있는지 보고
ffmpeg 를 켜고 끕니다.

```
통화 시작 ─▶ AGI 가 live/radio1/<통화ID> 파일을 만듦
                    │
          껍데기가 0.25초 안에 보고 ffmpeg 를 띄움  ─▶ 소리
                    │
 통화 끝 ──▶ h 확장에서 AGI 가 그 파일을 지움
                    │
          마지막 사람이었으면 5분(여운) 뒤 ffmpeg 를 내림  ─▶ 0 bytes/s
```

**고른 채널 하나만 받습니다.** 메뉴를 보는 동안 미리 붙여 두는 것도 해
봤지만 뺐습니다 — 고르지도 않은 채널을 받게 되고, 누르자마자 소리가
통째로 튀어나오는 것도 부자연스럽습니다. 대신 **서서히 켭니다**(아래).

**여운(`linger_sec`, 기본 5분)** 이 있는 이유 — 마지막 사람이 끊자마자 바로
끄면, 끊고 다시 걸거나 채널을 돌리다 돌아올 때마다 1~2초를 기다립니다.
5분을 더 받아 두면 그런 경우가 거의 다 없어집니다. 위의 미리 데우기까지 겹쳐서, 실제로 기다리게 되는 경우는 거의 없습니다.

껍데기는 방송을 안 받는 동안에도 **파이프를 붙잡은 채로** 잡니다. Asterisk
쪽에서 보면 EOF 가 아니라 데이터가 안 오는 상태라, 파이프 읽기에서 조용히
멈춰 있습니다. 그래서 클래스가 죽거나 재시도가 돌지 않습니다.

계속 받아 두고 싶으면 `"on_demand": false`.

### 왜 음악대기(MOH) 인가

Asterisk 에서 **끝없이 흐르는 소리**를 트는 방법은 이것뿐입니다.
`Playback()` 은 파일 하나를 끝까지 틀고 돌아옵니다. 스트림은 끝이 없습니다.

MOH 의 `mode=custom` 은 "명령을 하나 띄우고 그 표준출력을 오디오로 읽는다"는
뜻입니다. FreePBX GUI 기능이 아니라 Asterisk 코어 기능이라 설정 파일에 적으면
그만입니다. 그래서 이 프로젝트는 FreePBX 웹을 한 번도 안 씁니다.

**중요한 건 `format=slin16` 한 줄입니다.** 빠뜨리면 Asterisk 가 8kHz 로
해석해서 소리가 느리고 낮게(피치가 반으로) 나옵니다. 원인을 짐작하기
어려운 증상이라 `radio-gen.py` 가 항상 같이 넣고 `verify.sh` 가 확인합니다.

### 왜 `MusicOnHold()` 가 아니라 `StartMusicOnHold()` + `WaitExten()` 인가

`MusicOnHold()` 는 DTMF 를 안 받습니다. 그걸로 만들면 **채널을 바꿀 때마다
끊고 다시 걸어야 합니다.** `StartMusicOnHold()` 로 틀어 놓고 `WaitExten()` 으로
숫자를 기다리면, 듣는 도중에 누르는 순간 채널이 바뀝니다. 라디오 다이얼을
돌리는 것과 같습니다. `verify.sh` 가 이 구조가 유지되는지 확인합니다.

### 왜 ffmpeg 를 껍데기로 한 겹 감쌌나

1. **켜고 끄기** — 위에 쓴 on-demand. 이게 주된 이유입니다.
2. **스트림은 끊깁니다.** 방송국이 재시작하면 ffmpeg 가 죽습니다. 그대로
   두면 Asterisk 가 파이프의 EOF 를 보고 곧바로 다시 띄우는데, 방송국이 계속
   죽어 있으면 초당 수십 번 재시도하며 로그와 CPU 를 태웁니다. 껍데기는
   간격을 늘려 가며(1, 3, 5, 7, 9, 15초) 다시 붙고, 그동안에도 파이프를
   붙잡고 있어서 **듣던 사람의 통화가 안 끊깁니다.**
3. **Asterisk 는 이 명령을 셸이 아니라 `execv` 로 띄웁니다.** PATH 가 비어
   있을 수 있어 ffmpeg 를 못 찾습니다. URL 에 공백이 있으면 인자가 갈라져
   엉뚱한 주소로 붙습니다(`radiolib.py` 가 미리 거절합니다).

### 발신 화면이 안 뜨면 — 콜백으로 받습니다

**내가 7200 을 거는 발신 통화**는 내 전화기가 '발신자'라, 통화 중 화면 갱신이
안 되는 기종이 있습니다(모임스톤 등). 이 라디오는 **화면이 곧 메뉴**라
그게 안 되면 쓸 수가 없습니다.

그래서 7200 을 걸면 받고 잠깐 뒤 끊고, 시스템이 그 내선으로 **되걸어(콜백)**
수신으로 진행합니다. 수신은 발신자 이름이 확실히 뜹니다.

```
7200 발신 → 곧 끊김 → 3초 뒤 내 내선으로 콜백 → (자동응답) → 채널 목록
```

- 전화기가 **발신 중에도 화면을 잘 바꿔 준다면 콜백은 군더더기입니다.**
  다이얼플랜 전역 변수 `RD_NOCB=1` 로 끄면 걸자마자 메뉴가 뜹니다.
- 자동 응답은 전화기 자체 설정(Auto Answer)에 맡깁니다 — SIP 헤더를 안
  붙입니다. 안 켜면 그냥 벨이 울리고, 받으면 메뉴가 나옵니다.
- 콜백 지연은 기본 3초(`RADIO_CB_DELAY`). 너무 짧으면 끊는 순간과 겹쳐
  첫 콜백이 안 받아지고 부재중이 하나 찍힙니다.
- 외부·트렁크처럼 내선이 아닌 발신은 콜백하지 않고 바로 진행합니다.
- 콜백 call file 을 못 만들어도 **그 통화에서 그냥 메뉴로 넘어갑니다.**
  화면이 안 바뀌는 기종이면 그때는 번호를 눌러 가며 찾아야 합니다.
- **콜백으로 들어온 통화에서 `${CALLERID(num)}` 은 걸었던 내선이 아닙니다.**
  call file 의 `CallerID:`(=7200) 입니다. 그래서 콜백이 내선 번호를
  `Setvar: RD_EXT` 로 실어 보내고, 다이얼플랜이 그걸 먼저 씁니다. 로그에
  누가 무엇을 들었는지 남기는 데 씁니다.

## 다른 방식과 비교

Asterisk 로 전화 라디오를 만드는 길은 몇 가지가 있습니다. 소스를 확인하고
고른 결과입니다.

| 방식 | 구조 | 왜 안 골랐나 |
|---|---|---|
| **`MP3Player(url)`** | 다이얼플랜 한 줄. 제일 간단 | **누른 숫자를 안 알려 줍니다.** DTMF 가 오면 `res = 0; goto bail` 로 빠져나올 뿐 어떤 키였는지 버립니다. 채널을 돌리려면 매번 메뉴로 돌아가야 합니다. mpg123 전용이라 AAC·HLS 도 못 읽고, **통화마다 프로세스가 하나씩** 뜹니다 |
| **MOH `digit=`** | musiconhold.conf 만으로 채널 전환 | 클래스당 숫자 하나뿐이고, **MOH 가 숫자를 먼저 먹어서** 화면·목록·종료가 전부 안 먹습니다. 그래서 생성되는 설정에 "넣지 마세요" 주석을 박아 뒀습니다 |
| **ConfBridge + 송출 채널** | 회의방에 스트림 한 개를 넣고 다 참여 | 스트림 공유는 MOH 가 이미 해 줍니다. 채널 전환이 '회의방 이동'이 돼서 훨씬 무겁습니다 |
| **ARI / ExternalMedia** | 외부 앱이 RTP 를 직접 다룸 | 상주 서비스와 미디어 처리를 직접 짜야 합니다. 개인용 라디오에 맞는 무게가 아닙니다 |
| **MOH `mode=custom` + `StartMusicOnHold` + `WaitExten`** ← 이것 | 스트림은 MOH 가, 키 입력은 다이얼플랜이 | — |

### 소스에서 확인한 것

고른 이유가 짐작이 아니라는 근거입니다. 전부 `res_musiconhold.c` 의
`monmp3thread()` 에 있습니다.

- **스트림은 방송국당 한 번만 받습니다.** 받은 소리를
  `AST_LIST_TRAVERSE(&class->members, ...)` 로 듣는 사람 전부에게 나눠 씁니다.
  1명이든 10명이든 프로세스는 하나이고, 그래서 이미 데워진 채널로는 전환이
  즉시입니다.
- **아무도 안 들어도 계속 받습니다.** 스레드가 클래스 등록 때
  (`init_app_class` → `ast_pthread_create_background`) 뜹니다. 첫 통화 때가
  아닙니다. → **on-demand 껍데기가 필요한 이유입니다.**
- **`mode=custom` 은 `directory=` 를 안 적으면 `dir` 이 자동으로 `"nodir"` 이
  됩니다.** 그래서 "듣는 사람이 없으면 읽기를 건너뛴다"는 최적화가 우리
  클래스에는 안 걸리고, Asterisk 가 계속 파이프를 비워 줍니다.
  → **여운 시간 동안 소리가 고이지 않습니다.** 다시 들어와도 2초 전 소리가
  아니라 지금 소리가 나옵니다.
- **파이프가 EOF 면 곧바로 죽이고 다시 띄웁니다.** 사이에 간격이 없습니다.
  → 껍데기가 stdout 을 절대 안 닫는 이유입니다.
- **`kill_method` 기본값이 `process_group`** 이라 Asterisk 가 껍데기를 죽일 때
  자식 ffmpeg 도 같이 갑니다. 껍데기의 trap 은 그 위의 두 번째 안전장치입니다.

## 이런 경우엔 이렇게 됩니다

### 쓰다가

| 상황 | 어떻게 되나 |
|---|---|
| 통화가 없을 때 | **어느 방송국에도 안 붙어 있습니다.** `--status` 의 ffmpeg 0개가 정상입니다 |
| 듣는 중 | 고른 채널 **하나만** 받습니다 |
| 수화기를 내려놓는 걸 잊음 | 3시간이면 끊습니다 (`max_sec`) |
| 없는 번호를 누름 | 화면으로 알리고, 그 2초 동안에도 다음 번호가 먹습니다 |
| 어디서든 `0` 을 누름 | 채널 목록으로 갑니다 ("0번 채널은 없습니다" 가 뜨지 않습니다) |
| 메뉴에서 `#` 을 누름 | 종료됩니다. `Read()` 를 안 쓰는 이유가 이것입니다 |
| 방송이 계속 안 붙음 | 화면에 `(안나옴)`. `--status` 에 사유와 실패 횟수 |
| 껍데기가 안 떠 있음 | 화면에 `(준비안됨)`. 무음의 이유를 전화기에서 바로 알려 줍니다 |
| `moh reload` 직후 | 죽는 껍데기가 살아 있는 쪽 상태를 못 덮어씁니다 (예전엔 재설치마다 전 채널에 `(준비안됨)` 이 떴습니다) |
| 방송국이 죽음 | 간격을 늘려 가며 다시 붙습니다. 통화는 안 끊깁니다 |
| 채널 목록이 깨짐 | "채널 설정 오류" 후 종료. 반쯤 돌지 않습니다. 이유는 `radio.log` 에 |
| 채널 목록이 깨진 채로 통화 종료 | **그래도 '듣는 중' 표시는 거둡니다.** 안 그러면 아무도 안 듣는 방송을 몇 시간 받습니다 |
| 통화가 비정상 종료 | 표시가 남지만 만료(통화 최대 길이+1시간) 뒤 자동 청소. 급하면 `--reset` |

### 설정을 고칠 때

| 상황 | 어떻게 되나 |
|---|---|
| 편집하다 JSON 을 깨뜨림 | **듣던 라디오가 안 죽습니다.** 아무것도 안 바꾸고 옛 설정 그대로 |
| **듣는 중에 채널 목록을 고침** | **듣던 사람은 그대로 계속 듣습니다.** 없어진 채널의 표시만 치웁니다 |
| 저장을 여러 번 함 | 감시 단위가 oneshot 이고, 반영끼리는 잠금으로 한 번에 하나만 돕니다 |
| `key` 를 0 이나 `*` 로 씀 / 겹침 / URL 에 공백 | 반영 때 거절합니다 |
| `--add` 로 이상한 값 | 진짜 파일을 덮기 전에 검사해서 막습니다 |
| 주소는 맞는데 소리가 안 남 | `--check` 가 **무음 5초**를 잡아냅니다 |
| 번호가 이미 쓰이는 중 | 넣기 전에 멈춥니다 (남의 내선을 조용히 가리지 않게) |
| 나중에 같은 번호로 내선을 만듦 | `verify.sh` 가 가려진 내선을 찾아 알려 줍니다 |

### 설치·시스템

| 상황 | 어떻게 되나 |
|---|---|
| 설치를 두 번 함 | 표시 구간만 갈아끼웁니다. 빈 줄 하나도 안 쌓입니다 |
| 같은 파일에 알람이 들어 있음 | 표시가 달라(`OMNI-RADIO` / `WAKEUP-KOREAN`) 서로 안 건드립니다 |
| `#include` 가 우리 컨텍스트 아래 있음 | 파일 전체에 걸리는 지시자라 **위치와 상관없이 남깁니다** |
| `musiconhold.conf` 에 `#include` 가 없음 | 클래스가 파일에만 있고 Asterisk 는 모르는 상태. **증상이 무음뿐이라** 반영이 직접 넣고 `verify.sh` 가 매번 확인 |
| 로그 파일이 root 소유 | 통화 중 AGI 가 조용히 못 쓰게 됩니다. 설치 때 미리 asterisk 소유로 |
| Asterisk 가 껍데기를 죽임 | 자식 ffmpeg 도 같이 데려갑니다 (고아가 계속 받지 않게) |
| 통화ID 에 이상한 글자 | 파일 이름이 되므로 걸러 냅니다 (경로 탈출 방지) |

## 알아 둘 것

- **`#` 이 안 먹는 전화기가 있습니다.** `#` 를 DTMF 로 안 보내고 '발신' 키로
  쓰는 기종이 그렇습니다. 그때는 그냥 끊으면 됩니다(`h` 에서 표시를 거둡니다).
- **긴 통화가 CDR 에 남습니다.** 두 시간을 들으면 두 시간짜리 통화 한 건입니다.
  짧게 하려면 `idle_sec` 를 줄이세요.
- **G.722 로 붙는지 확인하세요.** ulaw 로 붙으면 소리는 나오지만 8kHz 로
  깎입니다. 통화 중에 `sudo asterisk -rx 'core show channels verbose'` 로 봅니다.
- **재송출은 저작권 문제가 될 수 있습니다.** 개인·사내용을 넘어 쓴다면
  확인이 필요합니다.

## 알람(freepbx-korean-alarm) 과 같이 쓸 때

같은 `extensions_custom.conf` 를 쓰지만 표시가 서로 달라 안 부딪칩니다.
전화기 화면 설정(`send_rpid` / `send_pai` / `CONNECTEDLINE(pres)`)도 같은
것을 쓰므로, 알람 쪽 `enable-display.sh` 를 이미 돌렸다면 라디오도 그대로
화면이 뜹니다.

```
7000  알람 · 모닝콜   (freepbx-korean-alarm)
7200  라디오          (omni-radio)
```
